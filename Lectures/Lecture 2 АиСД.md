## 0. Ретроспектива

На прошлой лекции были:
- инварианты циклов;
- доказательство корректности через `INIT`, `MNT`, `TRM`;
- точная функция временной сложности $T(n)$;
- асимптотически точная оценка $\Theta(g(n))$.

### Инвариант бесконечного цикла

Даже если цикл бесконечный, у него может быть инвариант. В этом случае он нужен не для доказательства завершения, а для доказательства промежуточной корректности: после каждой итерации система остается в согласованном состоянии.

Пример: скользящее среднее по потоку данных.

```cpp
std::queue<double> window;
double cur_sum = 0.0;
const int WINDOW_SIZE = 5;

while (true) {
    double val = read_sensor();
    window.push(val);
    cur_sum += val;

    if (window.size() > WINDOW_SIZE) {
        cur_sum -= window.front();
        window.pop();
    }

    double avg = cur_sum / window.size();
}
```

Инвариант в конце каждой итерации:
$$cur\_sum = \sum window$$
$$|window| \leq WINDOW\_SIZE$$

Смысл: сумма `cur_sum` всегда соответствует текущему содержимому очереди, а очередь не становится больше заданного окна.

> Важно: чтобы деление `cur_sum / window.size()` было безопасным, размер окна должен быть положительным.

## 1. Символ $\Theta$

$T(n)=\Theta(g(n))$, если $T(n)$ асимптотически зажата между двумя положительными константными множителями функции $g(n)$:

$$c_1g(n) \leq T(n) \leq c_2g(n)$$

для некоторых $c_1,c_2>0$ и всех достаточно больших $n$.

### Что означает $\Theta$

- $\Theta$ задает точный порядок роста.
- При использовании $\Theta$ нельзя искусственно завысить порядок.
- При использовании $\Theta$ нельзя занизить порядок.

Примеры:

$$T(n)=\frac{1}{2}n^2-3n=\Theta(n^2)$$

Можно выбрать:
$$n_0=7,\quad c_1=\frac{1}{14},\quad c_2=\frac{1}{2}$$

А вот:
$$n+1 \neq \Theta(n^2)$$
$$n^3-2n^2+1 \neq \Theta(n)$$

## 2. Асимптотическая верхняя граница: $O$

$T(n)=O(g(n))$, если функция $T(n)$ сверху ограничена функцией $g(n)$ с точностью до константы:

$$0 \leq T(n) \leq c g(n)$$

для некоторых $c,n_0>0$ и всех $n \geq n_0$.

### Смысл $O$

$O(g(n))$ говорит: алгоритм растет не быстрее, чем $g(n)$, если отбросить константы и малые значения $n$.

Если:

$$T(n)=\Theta(n^3)$$

то автоматически:

$$T(n)=O(n^3)$$

Но верхнюю границу можно брать и грубее:

$$3n = O(n^2)$$

Это корректно, потому что $n^2$ растет быстрее $n$.

### Пример с вложенными циклами

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < i; ++j) {
        for (int k = 0; k < j; ++k) {
            sum += i + j + k;
        }
    }
}
```

Оценка:

- внутренний цикл по `k`: $\Theta(j)$;
- цикл по `j`: $\sum_{j=0}^{i-1} j = \Theta(i^2)$;
- цикл по `i`: $\sum_{i=0}^{n-1} i^2 = \Theta(n^3)$.

Итого:

$$T(n)=\Theta(n^3)=O(n^3)$$

---
## 3. Асимптотическая нижняя граница: $\Omega$

$T(n)=\Omega(g(n))$, если функция $T(n)$ снизу ограничена функцией $g(n)$ с точностью до константы:

$$T(n) \geq c g(n) \geq 0$$

для некоторых $c,n_0>0$ и всех $n \geq n_0$.

### Смысл $\Omega$

$\Omega(g(n))$ говорит: алгоритм растет не медленнее, чем $g(n)$.

Например:

$$n^2 = \Omega(n)$$

Потому что квадратичная функция растет как минимум не медленнее линейной.

Для сортировки вставками:
- лучший случай: массив уже отсортирован;
- сложность лучшего случая: $\Theta(n)$;
- значит, временная сложность имеет нижнюю границу $\Omega(n)$.

---
## 4. Связь между $O$, $\Omega$ и $\Theta$

Главная связь:

$$T(n)=\Theta(g(n)) \iff T(n)=O(g(n)) \text{ и } T(n)=\Omega(g(n))$$

То есть $\Theta$ появляется тогда, когда у функции одновременно есть верхняя и нижняя граница одного порядка.

### Мини-задача из лекции

Даны:

$$T_1(n)=n^{\log_4 8}$$

$$T_2(n)=\frac{\sqrt{n^3}}{\log_2 n}$$

Так как:

$$\log_4 8=\frac{3}{2}$$

то:

$$T_1(n)=n^{3/2}$$

А:

$$T_2(n)=\frac{n^{3/2}}{\log_2 n}$$

Значит $T_2$ меньше $T_1$ на логарифмический множитель:

$$T_2(n)=O(T_1(n))$$

$$T_1(n)=\Omega(T_2(n))$$

## 5. Абстрактный тип данных

**Абстрактный тип данных**, или **ADT**, описывает интерфейс и ожидаемое поведение структуры, но не раскрывает внутреннюю реализацию.

Пример общей модели: `Container<T>`.

Контейнер может поддерживать:
- жизненный цикл: создание, копирование, перемещение, уничтожение;
- наблюдатели: `empty`, `size`, `capacity`, `count`, `contains`;
- модификаторы: `insert`, `remove`, `clear`;
- операции поиска и итерации: `find`, `begin`, `end`;
- операции порядка: `less`, `equal`, `lower_bound`, `upper_bound`, `sort`.

### ADT как контракт

ADT отвечает на вопрос:

> Какие операции доступны пользователю?

Структура данных отвечает на вопрос:

> Как эти операции реализованы внутри?

Пользователь работает с публичным интерфейсом, а детали хранения находятся в `private`-части класса.

## 6. Отношения между объектами

Контейнеры часто зависят от того, какое отношение задано между объектами.

### Линейный порядок

Отношение $\leq$ называется линейным порядком, если оно:
- рефлексивно: $x \leq x$;
- антисимметрично: если $x \leq y$ и $y \leq x$, то $x=y$;
- транзитивно: если $x \leq y$ и $y \leq z$, то $x \leq z$;
- сильно связно: любые два объекта сравнимы.

Примеры:
- числа;
- символы;
- строки в лексикографическом порядке.

Линейный порядок позволяет искать порядковые статистики, интервалы, предыдущий и следующий элементы.

### Частичный порядок

Частичный порядок обладает рефлексивностью, антисимметричностью и транзитивностью, но не требует сравнимости любых двух объектов.

Пример: зависимости в ориентированном ациклическом графе.

Можно спрашивать:
- есть ли предок;
- какие вершины не имеют предков;
- какие объекты являются потомками.

### Иерархия

Иерархия похожа на частичный порядок, но у предков объекта есть линейная структура: если два объекта являются предками одного объекта, то один из них должен быть предком другого.

Пример: области видимости в программе.

Для иерархии важны операции:
- проверить связь родитель-потомок;
- понять, находятся ли элементы на одном уровне;
- найти ближайшего общего предка.

### Эквивалентность

Отношение $\sim$ называется эквивалентностью, если оно:
- рефлексивно: $x \sim x$;
- симметрично: если $x \sim y$, то $y \sim x$;
- транзитивно: если $x \sim y$ и $y \sim z$, то $x \sim z$.

Эквивалентность разбивает множество на классы:

$$[x]=\{y \in X \mid y \sim x\}$$

Типичная структура данных: система непересекающихся множеств.

### Слабый порядок

Слабый порядок упорядочивает не обязательно отдельные объекты, а классы эквивалентности.

Пример в C++: результат трехстороннего сравнения может быть представлен через `std::weak_ordering`.

Контейнеры, где это важно:
- `std::set`;
- `std::map`;
- `std::multiset`;
- `std::multimap`.

### Смежность

Граф можно понимать как произвольное бинарное отношение:

- вершины — объекты;
- ребра — факты связи между объектами.

Реализация графа может быть разной:
- список ребер;
- список смежности;
- матрица смежности.

## 7. Размещение структур данных в памяти

Эффективность ADT во многом зависит от того, как данные лежат в памяти.

### Непрерывное размещение

Пример: динамический массив.

Свойства:
- объекты лежат подряд;
- быстрый доступ по индексу: $O(1)$;
- хорошая пространственная локальность;
- при нехватке емкости нужен новый блок памяти и копирование элементов.

Примеры:
- `std::vector`;
- `std::array`;
- `std::string`.

### Связное размещение

Пример: связный список.

Свойства:
- каждый узел хранит значение и указатель на следующий узел;
- быстрая вставка после известного узла;
- медленный произвольный доступ;
- поиск обычно требует прохода по списку.

Примеры:
- `std::list`;
- `std::forward_list`.

### Индексированное размещение

Пример: хеш-таблица или массив бакетов.

Свойства:
- есть индексная структура;
- при хорошем ключе вставка и поиск могут быть $O(1)$;
- производительность падает при большой вложенности, коллизиях или плохой организации памяти.

Примеры:
- `std::unordered_map`;
- `std::unordered_set`.

### Сравнение схем

| Размещение | Доступ по индексу | Вставка | Поиск | Примеры |
|---|---:|---:|---:|---|
| непрерывное | $O(1)$ | $O(n)$ | $O(n)$ | `std::vector`, `std::array`, `std::string` |
| связное | $O(n)$ | $O(1)$ после известного узла | $O(n)$ | `std::list`, `std::forward_list` |
| индексированное | обычно нет | $O(1)$ в среднем | $O(1)$ в среднем | `std::unordered_map`, `std::unordered_set` |

## 8. ADT Связный список

Связный список хранит элементы в узлах. Каждый узел содержит значение и одну или несколько ссылок на другие узлы.

### Односвязный список

Узел:

```cpp
struct Node {
    T value {};
    Node* next = nullptr;
};
```

Свойства:
- можно быстро вставить элемент после известного узла;
- итерация только вперед;
- поиск и произвольный доступ медленные;
- стандартный аналог: `std::forward_list`.

### Двусвязный список

Узел:

```cpp
struct Node {
    T value {};
    Node* next = nullptr;
    Node* prev = nullptr;
};
```

Свойства:
- можно идти вперед и назад;
- быстро удалять известный узел;
- требуется больше памяти, потому что хранится два указателя;
- стандартный аналог: `std::list`.

### Циклический список

В циклическом списке последний узел ссылается обратно на первый.

Свойства:
- нет обычного конца через `nullptr`;
- при обходе нельзя писать наивный бесконечный цикл;
- нужно явно проверять возврат к начальному узлу.

Пример обхода:

```cpp
Node* cur = head;
do {
    visit(cur);
    cur = cur->next;
} while (cur != head);
```

## 9. Массив против списка на практике

Теоретически вставка в список после известного узла быстрее, чем вставка в середину массива:

- список: $O(1)$;
- массив: $O(n)$ из-за сдвига элементов.

Но на практике массив часто выигрывает из-за пространственной локальности: соседние элементы лежат рядом в памяти и лучше используют кэш процессора.

Вывод: асимптотика важна, но не заменяет понимание реальной модели памяти.

## 10. Проблемы `new`

Выделение памяти через `new` кажется простым, но у него есть подводные камни:

- может нарушиться сильная гарантия исключений;
- есть накладные расходы на работу с кучей;
- возможны блокировки;
- нужно учитывать выравнивание;
- частые мелкие выделения памяти ухудшают производительность.

### Почему `unique_ptr` не решает все

`std::unique_ptr` помогает управлять владением памятью, но не всегда решает архитектурную проблему.

Например, если каждый узел владеет следующим через `unique_ptr`, уничтожение длинного списка может вызвать рекурсивную цепочку деструкторов и переполнить стек.

Поэтому в реализациях списков часто используют:
- обычные указатели внутри узлов;
- явный итеративный деструктор списка;
- отдельную стратегию управления памятью.

## 11. Пул памяти

**Пул памяти** — заранее выделенная область, из которой структура данных берет узлы.

Идея:
- заранее создать массив узлов;
- хранить список свободных ячеек `free_list`;
- при `allocate()` брать первый свободный узел;
- при `deallocate()` возвращать узел обратно в список свободных.

Так выделение и освобождение узла работают за:

$$\Theta(1)$$

### Зачем нужен пул памяти

Пул памяти уменьшает:
- количество обращений к общей куче;
- накладные расходы на частые `new/delete`;
- фрагментацию;
- непредсказуемость времени выделения.

Но пул памяти требует заранее понимать или ограничивать емкость.

## 12. Главное за лекцию

- $O(g(n))$ — верхняя асимптотическая граница.
- $\Omega(g(n))$ — нижняя асимптотическая граница.
- $\Theta(g(n))$ — точный порядок роста, то есть одновременно верхняя и нижняя граница одного порядка.
- ADT задает контракт операций, а структура данных определяет внутреннюю реализацию.
- Отношения между объектами влияют на то, какие операции естественны для контейнера.
- Размещение в памяти сильно влияет на эффективность.
- Связные списки дают быструю вставку после известного узла, но проигрывают в поиске и локальности.
- `new` и `delete` не бесплатны; для частых выделений узлов может использоваться пул памяти.

На следующей лекции: рекурсивные алгоритмы и парадигма «разделяй и властвуй».
