## 0. Ретроспектива: асимптотические границы

Для достаточно больших $n$:

$$T(n)=O(g(n))\iff 0\leq T(n)\leq c_2g(n)$$
$$T(n)=\Omega(g(n))\iff 0\leq c_1g(n)\leq T(n)$$
$$T(n)=\Theta(g(n))\iff 0\leq c_1g(n)\leq T(n)\leq c_2g(n)$$

Здесь $c_1,c_2>0$ — постоянные множители. Значит:

$$\Theta(g(n))=O(g(n))\cap\Omega(g(n))$$

### Мини-задача

Известно:

$$T(n)=T_1(n)+T_2(n),\qquad T_1(n)=O(n^3),\qquad T_2(n)=\Omega(n^2)$$

Для неотрицательных функций сложности всегда верно:

$$T(n)=\Omega(n^2)$$

Потому что $T(n)\geq T_2(n)$. Верхняя граница для $T_2$ не задана: например, $T_2(n)=n^4$ тоже удовлетворяет условию. Поэтому $O(n^3)$ для суммы не гарантируется.

## 1. Интрузивный список

**Интрузивный список** хранит связи между элементами внутри самих объектов, а не в отдельно выделенных узлах контейнера.

### Один объект в нескольких списках

Например, сетевое соединение может одновременно находиться:

- в списке всех соединений;
- в списке соединений, готовых к обработке.

При использовании `std::list<Connection*>` объект не копируется, но каждый список всё равно хранит собственные узлы с указателями. Вставки требуют дополнительных аллокаций.

Интрузивный вариант встраивает отдельные пары `next/prev` для каждой независимой принадлежности к списку.

### Теги

Тег позволяет различать наборы связей на уровне типов:

```cpp
#include <string>

struct AllTag {};
struct ReadyTag {};

template <typename Tag>
struct Links {
    Links* next = nullptr;
    Links* prev = nullptr;
};

struct Connection : Links<AllTag>, Links<ReadyTag> {
    int socket_fd = -1;
    std::string buffer;
};
```

`Links<AllTag>` и `Links<ReadyTag>` — разные типы. Один `Connection` содержит оба набора связей и может участвовать в двух списках одновременно.

### Пример связей

```cpp
Connection first, second;
first.socket_fd = 10;
second.socket_fd = 11;

first.Links<AllTag>::next = &second;
second.Links<AllTag>::prev = &first;

// Порядок во втором списке может быть другим.
second.Links<ReadyTag>::next = &first;
first.Links<ReadyTag>::prev = &second;
```

Чтобы получить объект из указателя на его базовую часть, можно использовать `static_cast<Connection*>`, если узел действительно принадлежит живому `Connection`.

### Что важно

- Вставка не требует отдельного выделения узла списка.
- Для каждого списка нужен свой набор связей.
- Адрес объекта должен оставаться стабильным, пока он связан со списками.
- Перед уничтожением объекта его нужно исключить из всех списков.
- Владение объектами и организация связей — отдельные вопросы.

Например, перераспределение памяти `std::vector<Connection>` может переместить объекты и сделать указатели списка недействительными.

## 2. Рекурсивная сортировка выбором

Идея: найти минимальный элемент, поставить его в начало и рекурсивно отсортировать оставшуюся часть.

### Алгоритм

```cpp
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <vector>

// first — начало ещё не отсортированной части, 0 <= first <= a.size().
void selection_sort(std::vector<int>& a, std::size_t first = 0) {
    assert(first <= a.size());
    if (a.size() - first <= 1) return;

    auto begin = a.begin() + first;
    auto minimum = std::min_element(begin, a.end());
    std::iter_swap(begin, minimum);
    selection_sort(a, first + 1);
}

int main() {
    std::vector<int> a = {7, 2, 7, -1, 4};
    selection_sort(a);
    assert((a == std::vector<int>{-1, 2, 4, 7, 7}));
}
```

`first` показывает границу между уже обработанным префиксом и оставшейся частью. Минимум ищется только в оставшемся диапазоне.

Пример:

```text
[7, 2, 7, -1, 4]
[-1 | 2, 7, 7, 4]
[-1, 2 | 7, 7, 4]
[-1, 2, 4 | 7, 7]
[-1, 2, 4, 7 | 7]
```

## 3. Доказательство корректности и завершения

### Индукция по размеру диапазона

Пусть $P(n)$ означает: вызов сортировки для диапазона длины $n$ возвращает его отсортированным и сохраняет набор элементов.

1. **База:** $n=0$ или $n=1$. Диапазон уже отсортирован, алгоритм сразу возвращается.
2. **Предположение:** утверждение верно для всех меньших размеров.
3. **Переход:** минимум ставится в первую позицию, а рекурсивный вызов сортирует оставшиеся $n-1$ элементов. Первый элемент не больше любого элемента хвоста, поэтому весь диапазон отсортирован.

Обмены только переставляют элементы, поэтому ничего не теряется и не добавляется.

### Убывающая мера

**Мера рекурсии** — неотрицательная величина, которая строго уменьшается при переходе к следующему вызову.

Здесь:

$$n=|a|-first,\qquad n\longrightarrow n-1$$

Мера достигает $n\leq1$, где выполняется базовый случай. Это доказывает завершение для конечного массива в математической модели.

> Индукция доказывает свойство результата, а убывающая мера — завершение. На практике глубокая рекурсия также ограничена размером стека.

## 4. Рекуррентное соотношение для сортировки выбором

На диапазоне длины $n$:

- поиск минимума требует $\Theta(n)$ работы;
- обмен — $O(1)$;
- один рекурсивный вызов обрабатывает $n-1$ элементов.

Получаем:

$$T(n)=\begin{cases}
\Theta(1),&n\leq1,\\
T(n-1)+\Theta(n),&n>1.
\end{cases}$$

### Итерационный метод

Последовательно раскрываем рекурсию:

$$T(n)\leq T(n-1)+kn$$
$$T(n)\leq T(n-2)+k(n-1)+kn$$
$$T(n)\leq T(1)+k\sum_{j=2}^n j$$

Так как:

$$\sum_{j=1}^n j=\frac{n(n+1)}2$$

получаем $T(n)=O(n^2)$.

В этой реализации поиск минимума на диапазоне длины $j$ делает $j-1$ сравнений. Общее число сравнений:

$$\sum_{j=2}^n(j-1)=\frac{n(n-1)}2$$

Значит, точный порядок:

$$T(n)=\Theta(n^2)$$

Он одинаков по порядку для уже отсортированного, обратного и произвольного массива: минимум каждый раз ищется проходом по хвосту.

### Память

Обмену достаточно $O(1)$ дополнительной памяти, но одновременно активны до $O(n)$ рекурсивных вызовов:

$$S(n)=O(n)$$

Итеративная сортировка выбором может обходиться $O(1)$ дополнительной памятью.

## 5. Метод подстановки и математической индукции

### Проверяем квадратичную верхнюю границу

Предполагаем $T(m)\leq cm^2$ для меньших размеров. Тогда:

$$T(n)\leq c(n-1)^2+kn$$
$$T(n)\leq cn^2-((2c-k)n-c)$$

Для сохранения $T(n)\leq cn^2$ достаточно:

$$(2c-k)n-c\geq0$$

Например, при $c\geq k$ это выполняется для $n\geq1$. Увеличиваем $c$, если нужно покрыть базовый случай.

Здесь $k$ задаётся стоимостью операций алгоритма, а $c$ выбирается для доказательства оценки.

### Почему попытка $O(n)$ не проходит

С гипотезой $T(m)\leq cm$ подстановка даёт:

$$T(n)\leq c(n-1)+kn=cn+(kn-c)$$

Чтобы этот способ сохранил оценку, пришлось бы требовать $kn\leq c$, то есть $n\leq c/k$. Это не работает для всех достаточно больших $n$.

> Неудачная подстановка сама по себе не доказывает ложность любой гипотезы. Здесь линейную оценку отдельно опровергает уже найденное число сравнений $n(n-1)/2$.

## 6. Парадигма «разделяй и властвуй»

Три шага:

1. Разделить исходную задачу на меньшие подзадачи.
2. Рекурсивно решить каждую подзадачу.
3. Объединить частичные ответы.

Для сортировки слиянием:

- делим массив на две примерно равные половины;
- сортируем обе половины;
- сливаем два отсортированных диапазона в один.

### Слияние

Держим указатель на первый ещё не взятый элемент каждой половины. Выбираем меньший, переносим в результат и двигаем его указатель.

```text
левая половина:  [-1, 7]
правая половина: [2, 4, 7]

результат: [-1, 2, 4, 7, 7]
```

Каждый элемент переносится один раз, поэтому слияние с отдельным буфером занимает $\Theta(n)$.

### Устойчивость

**Устойчивая сортировка** сохраняет исходный относительный порядок элементов с одинаковыми ключами.

При равенстве нужно сначала выбирать элемент из левой половины. Например, записи `(7, первый)` и `(7, второй)` останутся в том же порядке.

Обычная сортировка выбором с обменом минимума неустойчива: на ключах `[2a, 2b, 1]` первый обмен даёт `[1, 2b, 2a]`.

## 7. Сортировка слиянием с общим буфером

Буфер выделяется один раз; рекурсивные вызовы используют его соответствующие диапазоны. Само слияние выполняет стандартный `std::merge`.

```cpp
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <vector>

// Внутренний вызов: buffer отдельный от a и имеет такой же размер.
// Границы задают корректный полуинтервал [first, last).
void merge_sort_part(std::vector<int>& a, std::vector<int>& buffer,
                     std::size_t first, std::size_t last) {
    if (last - first <= 1) return;
    std::size_t mid = first + (last - first) / 2;

    merge_sort_part(a, buffer, first, mid);
    merge_sort_part(a, buffer, mid, last);

    std::merge(a.begin() + first, a.begin() + mid,
               a.begin() + mid, a.begin() + last,
               buffer.begin() + first);
    std::copy(buffer.begin() + first, buffer.begin() + last,
              a.begin() + first);
}

void merge_sort(std::vector<int>& a) {
    std::vector<int> buffer(a.size());
    merge_sort_part(a, buffer, 0, a.size());
}

int main() {
    std::vector<int> a = {7, 2, 7, -1, 4};
    merge_sort(a);
    assert((a == std::vector<int>{-1, 2, 4, 7, 7}));
}
```

`std::merge` требует отсортированных входных диапазонов и выходного диапазона, не пересекающегося с ними. Здесь результат сначала записывается в отдельный `buffer`, затем копируется обратно. Слияние устойчиво. См. [контракт `std::merge`](https://eel.is/c++draft/alg.merge).

### Корректность

- Диапазон длины 0 или 1 уже отсортирован.
- По индукции оба рекурсивных вызова возвращают отсортированные половины.
- Слияние возвращает отсортированное объединение с теми же элементами.

Для $n>1$ обе половины строго меньше исходного диапазона, поэтому рекурсия завершается.

## 8. Дерево рекурсии и сложность слияния

При $n$ — степени двойки:

$$T(n)=2T(n/2)+kn,\qquad T(1)=t_0$$

На уровне $i$:

- $2^i$ подзадач;
- размер каждой $n/2^i$;
- суммарная дополнительная работа $2^i\cdot kn/2^i=kn$.

Глубина до листьев — $\log_2 n$ рёбер. Всего уровней вместе с листьями — $\log_2 n+1$.

На внутренних уровнях суммируем $kn$, а $n$ листьев дают $nt_0$:

$$T(n)=kn\log_2 n+nt_0=\Theta(n\log n)$$

### Что происходит с памятью

- Общий буфер: $O(n)$.
- Стек: $O(\log n)$, потому что одновременно активна одна ветка вызовов.
- Суммарно дополнительная память: $O(n)$.

Число вызовов и глубина стека — разные величины. В полном бинарном дереве с $n$ листьями $2n-1$ узлов, но одновременно на стеке находится только путь от корня к текущему узлу.

## 9. Проверка оценок подстановкой

### Линейная гипотеза

Для $T(m)\leq cm$:

$$T(n)\leq2c(n/2)+kn=cn+kn$$

Дополнительная линейная работа не поглощается выбранной гипотезой. Дерево рекурсии показывает, что действительный порядок — $n\log n$.

### Квадратичная гипотеза

Для $T(m)\leq cm^2$:

$$T(n)\leq2c(n/2)^2+kn=\frac{cn^2}{2}+kn$$

Это не больше $cn^2$ при $n\geq2k/c$. С учётом базы можно доказать $O(n^2)$, но это грубая верхняя граница.

### Гипотеза $n\log n$

Чтобы не возникла проблема $\log_2 1=0$ в базе, используем усиленную запись:

$$T(m)\leq cm\log_2 m+dm$$

Тогда:

$$T(n)\leq2\left(c\frac n2\log_2\frac n2+d\frac n2\right)+kn$$
$$T(n)\leq cn\log_2 n+dn-(c-k)n$$

Достаточно выбрать $c\geq k$ и $d\geq T(1)$. Получаем $T(n)=O(n\log n)$.

> Разные корректные верхние границы не противоречат друг другу: $\Theta(n\log n)$ одновременно даёт $O(n\log n)$ и $O(n^2)$.

## 10. Округления размеров подзадач

Для произвольного целого $n$ точная модель:

$$T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+\Theta(n)$$

Например, диапазон длины 5 делится на части длины 2 и 3.

### Почему порядок сохраняется

- Самая длинная ветка имеет глубину $\lceil\log_2 n\rceil$.
- На каждом уровне диапазоны не пересекаются и их суммарная длина не больше $n$.
- Работа уровня ограничена $O(n)$.

Итого верхняя граница $O(n\log n)$. Для слияния, которое переносит каждый элемент, суммарная работа даёт и нижнюю границу того же порядка.

### Замена переменной из лекции

При монотонной модели стоимости:

$$T(n)\leq2T(n/2+1)+kn$$

Положим $S(x)=T(x+\alpha)$. Чтобы аргумент следующего вызова стал $x/2$, нужно:

$$\frac{x+\alpha}{2}+1=\frac x2+\alpha$$
$$\alpha=2$$

Тогда:

$$S(x)\leq2S(x/2)+k(x+2)$$

Дополнительная работа по-прежнему $O(x)$, поэтому $S(x)=O(x\log x)$ и $T(n)=S(n-2)=O(n\log n)$ для достаточно больших $n$.

> В равенстве определяется сдвиг $\alpha=2$, а не размер задачи $n=2$.

## 11. Варианты реализации слияния

| Вариант | Время всей сортировки | Буферы | Аллокации |
|---|---|---|---|
| общий буфер | $\Theta(n\log n)$ | $O(n)$ | одна для буфера непустого массива |
| локальный буфер при каждом слиянии | $\Theta(n\log n)$ | $O(n)$ в пике | $O(n)$ выделений |
| слияние последовательными сдвигами | $\Theta(n^2)$ в худшем случае | $O(1)$ для самого слияния | отдельный буфер не нужен |
| `std::inplace_merge` | зависит от доступной памяти | может использовать временный буфер | определяются реализацией |

Во всех рекурсивных вариантах дополнительно учитываем стек $O(\log n)$.

### Локальный буфер

Если буфер создаётся после возвращения дочерних вызовов, он не живёт одновременно с их буферами. Поэтому пик памяти $O(n)$, хотя сумма размеров всех выделенных за работу буферов равна $O(n\log n)$.

Частые аллокации добавляют накладные расходы. Общий буфер устраняет повторные выделения, не меняя асимптотики сортировки.

### Слияние сдвигами

Вариант из лекции переносит элемент правой половины в левую через `std::rotate`. Один такой перенос сдвигает целый участок.

Если все элементы правой половины меньше элементов левой, многократные переносы дают $\Theta(n^2)$ на слиянии. Поэтому:

$$T(n)=2T(n/2)+\Theta(n^2)=\Theta(n^2)$$

Внутри диапазона операция `std::rotate` имеет линейную верхнюю границу по числу обменов. См. [контракт `std::rotate`](https://eel.is/c++draft/alg.rotate).

### `std::inplace_merge`

Название означает, что результат остаётся в исходном диапазоне. Оно не гарантирует отсутствие вспомогательной памяти.

Для обычной перегрузки при достаточной дополнительной памяти слияние требует не более $n-1$ сравнений; иначе допускается $O(n\log n)$ сравнений. Поэтому для сортировки через этот вызов получается $O(n\log n)$ сравнений при линейных слияниях и верхняя граница $O(n\log^2 n)$ при переходе на запасной вариант. См. [контракт `std::inplace_merge`](https://eel.is/c++draft/alg.merge).

## 13. Главное за лекцию

- Завершение рекурсии доказывается убывающей мерой, корректность результата — индукцией.
- Сортировка выбором: $T(n)=T(n-1)+\Theta(n)=\Theta(n^2)$.
- Рекуррентные соотношения решают развёрткой, подстановкой с индукцией и деревом рекурсии.
- Сортировка с линейным слиянием: $T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)$.
- Важны стоимость слияния, количество аллокаций и пик памяти.
- Округления половин не меняют порядок $n\log n$, но требуют обоснования.
- Интрузивный список встраивает связи в объекты; время жизни и стабильность адресов нужно контролировать отдельно.
